# Aidos Documentation

Aidos documentation follows an RFC (Request for Comments) process to establish architecture, design decisions, and technical direction.

## Structure

### [Vision](./vision.md)

The mission and guiding punchline for Aidos as an AI Operating Environment.

### [Principles](./principles.md)

Ten core architectural principles that guide design decisions across all subsystems.

### [RFCs](./rfcs/)

Detailed technical specifications and design documents covering all major subsystems. Each RFC progresses through statuses: Draft → Accepted → Implemented (or Deprecated/Superseded).

### [Roadmap](./roadmap.md)

An index into the three levels of plan: RFC-0099 for the phases and their rationale,
[the MVP roadmap](./mvp-roadmap.md) for the ordered work breakdown, and
[`PIPELINE.md`](../PIPELINE.md) for live progress.

### [Decisions](./decisions.md)

Why the architecture is this and not something else, what each choice forecloses, and what it
would cost to revisit. Read it before proposing a change to a settled question.
